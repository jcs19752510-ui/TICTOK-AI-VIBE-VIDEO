# 에피소드 spec.json 작성 지침 (에이전트용)

목표: `에피소드_NN/spec.json` 하나를 완성한다. 이 파일에서 문서(A~H)와 영상 시간표가 자동 생성된다. 모델 예시는 `에피소드_03/spec.json`이다(필드 구조를 그대로 따른다).

## 먼저 읽을 것
1. `에피소드_03/spec.json` (모델), `에피소드_02/02_코딩몰라도앱고치기.md` (문체·완성된 문서 예시)
2. `aI바이브코딩주제30개.md` — 맡은 편의 한 줄 주제, 후킹 패턴, 1·2·3단계, 댓글 키워드, 그리고 **다음 편(NN+1) 주제**(장면 16 예고에 쓴다). 앞 편(NN-1) 주제도 본다(장면 2 연결 문장에 쓴다).
3. `공통제작도구/check_doc.py` (검증 규칙), `공통제작도구/build_episode.py` (필드 설명), `공통제작도구/player.html`의 `visual()` 함수 (쓸 수 있는 화면 종류)
4. `CLAUDE.md`의 "채널 규칙"

## 반드시 지킬 것
- 장면 16개, 각 2~5초, 합계 60~90초(70초 권장). 구성: 후킹 2초 → 앞 편 연결 → 공감 → 1단계(제목, 시연) → 2단계(제목, 시연, 결과) → 3단계(제목, 확인) → 안 될 때 → 요령 1개 → 개인정보·비밀번호 한 줄 → 요약 → CTA → 다음 편 예고(3초). 모델과 같은 순서를 따른다.
- 나레이션 음절(한글+숫자 글자 수) ≤ 장면 초 × 5.5. 화면 자막 ≤ 22자. 설명글 ≤ 500자, 첫 줄은 질문이나 반전, 끝에 `repro_note`("…재현 화면입니다.")가 붙는다. 해시태그 10개(대형3·중형4·소형3, 서로 중복 없음).
- 문체: "~됩니다/~합니다/~보겠습니다" 중심의 또렷한 설명 어투. "~해요/~줘요/~볼게요" 반복 금지. 경험 단정 금지("제가 직접", "저도", "해봤더니", "헤맸"). 과장 금지("무조건", "100%", "누구나", "1분 만에", "클릭 한 번"). "구독자", "조회수" 수치 언급 금지.
- 후킹 패턴은 표에 적힌 것으로 하고, 직전 편과 다른 방식으로 쓴다. 후킹은 첫 프레임부터 보여야 한다(장면 1은 페이드인 없음).
- **지어내지 않는다.** Claude 등 서비스의 메뉴명, 요금제, 기능명, 모델명, 통계, 속도 수치를 쓰지 않는다. 화면은 "AI 대화창"처럼 일반 표현만 쓴다. 확실하지 않은 것은 H의 `repro` 표에 "확인 필요"로 적는다. 실제 AI 답은 매번 다르다는 점을 `repro`에 사실대로 적는다(이 환경에서 실제로 시험하지 못했다).
- 예시 문서·메모·표는 **가상의 내용**으로 쓴다. 실제 사람 이름, 회사명, 연락처, 계정, 키를 쓰지 않는다.
- 장면 12의 요령은 1개만. 장면 13은 개인정보·비밀번호 주의 한 줄(대사에 "개인정보" 또는 "비밀번호" 포함).
- 장면 15 대사는 "댓글에 <키워드> 남겨 주시면, 프롬프트 템플릿을 드리겠습니다" 형식(키워드는 표의 것). 장면 16 대사는 "다음 편은 ○○입니다" 형식, 16음절 이하, 다음 편 주제를 반영.
- G `template`은 그 편의 1·2·3단계를 따라 쓸 수 있는 문장 틀과 "안 될 때" 문장을 포함한다.

## 화면(v) 길이 제한 (넘으면 글자가 잘린다)
- chat `typed`/`user` ≤ 90자, `ai` ≤ 40자, `list` 각 항목 ≤ 20자, 최대 3개. 긴 원문(회의 메모 등)을 붙여넣는 장면은 요약된 짧은 예시문(≤ 80자)으로 쓴다.
- ba(`panel`) 한쪽 `lines` 최대 5줄, 줄당 ≤ 18자. `h` ≤ 8자.
- app `banner` ≤ 40자, `items` 최대 4개, `tag` ≤ 14자. 앱 옵션: `dateCol`, `accent`(색상 코드), `bg`, `fs`(글자 배율, 예 1.3), `dark`. 항목: `t`, `due`, `late`, `done`.
- pills 항목 `t` ≤ 14자, 최대 3개. cards 3개, 제목 ≤ 6자, 설명 ≤ 14자. big `t` ≤ 12자(줄바꿈 \n), `sub` ≤ 16자.
- 화면 종류: app, chat, step, ba, baapp, pills, lock, cards, cta, end, big, **ledger, quiz, calc**.
- 앱 화면 3종(앱 만들기 편용): `ledger`(가계부: `title`, `items`[{t, amt}] 최대 4개, `total`, `tag`, `stamp`), `quiz`(`title`, `q` ≤ 24자, `choices` 3개 ≤ 10자, `pick`=정답 인덱스), `calc`(`title`, `fields`[[라벨, 값]] 최대 2개, `result` ≤ 18자). 모두 `now`, `banner`, `stamp`, `tag`, `accent`를 쓸 수 있다. 할 일 앱이 아닌 편에서는 `app`(할 일 목록) 대신 이것들을 쓴다.
- **첫 장면(후킹) v에는 `"now": true`를 넣는다**(첫 프레임부터 모든 요소를 보여 준다). `over`(동그라미 기호), `pill`(말풍선)은 일부 화면에 덧붙일 수 있다. `pill`을 쓰면 자막 영역(y>1050)과 겹치지 않는지 생각한다.
- step 장면은 n=1,2,3 순서로, icon은 bubble/cursor/wrench.

## 작업 방법
1. `에피소드_NN/spec.json`을 쓴다.
2. `python3 -I 공통제작도구/build_episode.py 에피소드_NN` 실행.
3. `python3 -I 공통제작도구/check_doc.py 에피소드_NN/NN_<slug>.md` 가 **20/20**이 될 때까지 spec을 고친다(T02는 음절 초과 장면을 알려 준다).
4. 만든 문서를 한 번 읽고 어색한 대사, 과장, 지어낸 사실이 없는지 점검한다.
5. 영상 렌더는 하지 않는다(메인이 한다). git 명령, 다른 편 폴더, 공통제작도구 파일 수정 금지. 쓰는 파일은 `에피소드_NN/` 아래뿐이다.
6. 마지막 보고(300자 이내): spec 경로, check 결과, 지어내지 않으려고 "확인 필요"로 남긴 것, 마음에 걸리는 점.
