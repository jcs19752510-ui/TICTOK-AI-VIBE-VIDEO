## 1. 개요
- 테스트 대상: 에피소드 기획 문서(`01_코딩몰라도앱만들었습니다.md`)와 완성 영상(`영상/ep01.mp4`), 썸네일(`영상/thumbnail.png`), 자막 SRT 2종, 설계 파일(`scenes.json`)
- 테스트 유형: 시스템(산출물 검수) + 보안 점검
- 적용 Tier: Standard (DEC-005). 규칙 B에 따라 최소 2회 검증
- 적용 속도 트랙: N/A (코드 기능 개발이 아니라 콘텐츠 제작)
- 병렬 실행 정보: 병렬 웨이브 사용 (P1, DEC-006). 프레임 캡처 6개 브라우저 동시, 검수와 보안 점검 동시 실행, 장면 생성기와 렌더러 동시 작성
- 테스트 목적: 영상이 기획(장면표, 규격, 채널 규칙)과 1:1로 일치하고, 틱톡 업로드에 적합하며, 개인정보·키·타사 브랜드가 없는지 확인
- 관련 산출물: `docs/harness/decisions.md`(DEC-001~014), `영상/scenes.json`
- 테스트 수행자: 오케스트레이터 세션(단일 에이전트). 서브에이전트는 사용하지 않았다
- 테스트 일시: 2026-10-13 05:43 ~ 06:01 UTC (영상 작업 시작부터 약 18분)

## 2. 테스트 범위 및 제외 범위
- 범위(In-Scope): 영상 규격(해상도·길이·프레임레이트·코덱·오디오), 자막 일치, 화면 안전 영역, 자막 대비, 문서 규칙 28항목, 보안 16항목, 장면 15개의 눈 검수
- 제외 범위와 사유
  - **틱톡 앱에서의 실제 재생·업로드**: 이 환경에서 불가능. 사용자가 직접 확인해야 함
  - **음성·BGM**: 무음으로 확정(DEC-010, DEC-013)이라 해당 없음(대상 자체가 없음)
  - **영상 안의 글자 판독(OCR)**: 도구가 없어 하지 않음. 글자는 설계 데이터(`scenes.json`)와 렌더러 코드에서 검증하고, 대표 프레임은 눈으로 확인함
  - **Claude 실제 메뉴명·요금제·해시태그 규모**: 지어내지 않고 '확인 필요'로 남김
  - **1인칭 경험 표현의 사실 여부**: 사용자만 알 수 있음. 아래 8절 참조
