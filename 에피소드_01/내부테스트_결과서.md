# 내부테스트 결과서 — 에피소드 1/30 "코딩 몰라도 앱 만들었습니다" (문서 + 영상 + 음성)

> 하네스 `templates/test-report-template.md`의 10개 절을 모두 작성했다. 시각은 모두 UTC이며 `date`로 잰 값이다. 이 결과서는 v2이며, 1차 결과서(무음 영상)를 음성 추가 작업(2026-10-13 06:03 요청)에 맞춰 전면 갱신한 것이다.

## 1. 개요
- 테스트 대상: 에피소드 기획 문서(`01_코딩몰라도앱만들었습니다.md`), 완성 영상(`영상/ep01.mp4`, AI 음성 포함), 썸네일, 자막 SRT 2종, 설계 파일(`scenes.json`), 음성 합성 스크립트(`make_voice.py`), `CLAUDE.md`
- 테스트 유형: 시스템(산출물 검수) + 보안 점검 + 재생 확인
- 적용 Tier: Standard (DEC-005). 규칙 B에 따라 최소 2회 검증
- 적용 속도 트랙: N/A (콘텐츠 제작)
- 병렬 실행 정보: 병렬 웨이브 사용 (P1, DEC-006). 프레임 캡처 6개 브라우저 동시, 검수·보안·재생 확인 동시, 음성 후보 2종 동시 합성, 폰트 확인·웹 검색·문서 정정 동시
- 테스트 목적: ① 음성이 들어간 영상이 기획과 일치하고 업로드에 적합한지 ② 재현 영상에 맞는 정직한 표현인지 ③ 개인정보·키·타사 브랜드가 없는지 ④ 폰트 라이선스와 '현재 기준' 정보가 근거 있는지
- 관련 산출물: `docs/harness/decisions.md`(DEC-001~034), `영상/scenes.json`, 얼굴 영상 합성기 `영상/build_final.py`, 시험 도구 `영상/make_fake_recordings.py`
- 테스트 수행자: 오케스트레이터 세션(단일 에이전트, 서브에이전트 미사용)
- 테스트 일시: 2026-10-13 06:03 ~ 06:30 UTC (음성 추가·정리), 07:48 ~ 08:12 UTC (후킹 문구 변경, 얼굴 영상 합성기 개발·시험, AI 음성 영상 재제작)

## 2. 테스트 범위 및 제외 범위
- 범위(In-Scope): 영상 규격, 음성(존재·음량·장면별 싱크·잘림), 자막 일치, 안전 영역, 표기(재현 화면·AI 음성), 문서 규칙 28항목, 보안 16항목, 재생 확인(대체 방식), 폰트 라이선스, '확인 필요' 항목의 현재 기준 확인
- 제외 범위와 사유
  - **사람 귀로 듣는 재생·음성 품질 평가**: 불가능. 음량·음성 구간·디코딩 바이트 등 측정으로 대체
  - **실제 mp4의 브라우저 직접 재생**: 이 환경의 Chromium이 H.264/AAC를 재생하지 못함. 대체 방식은 4-4 참조
  - **틱톡 앱 업로드·재생**: 사용자가 직접 수행(DEC-020)
  - **해시태그 규모 확인**: 틱톡 사이트 접속 불가(DNS 실패)와 검색 결과 부재로 수행 못함 → '확인 필요' 유지
  - **espeak-ng 대안 음성의 최종 대사 재시험**: 구글 방식이 성공해 최종 대사로는 재시험하지 않음(대상 자체가 없음)
  - 배경음악: 사용자 지시로 사용하지 않음(DEC-016)

## 3. 테스트 환경
- 실행 환경: Linux 6.18 클라우드 컨테이너, Chromium 141(Playwright 1.56.1), ffmpeg/ffprobe, Python 3.13(Pillow, NumPy, fontTools), Node 22
- 테스트 데이터: 에피소드 문서의 장면표(15장면)에서 생성한 `scenes.json`
- 전제 조건: 폰트 Noto Sans KR 500·900(임시 폴더). 인코딩 H.264 crf 18, 30fps, AAC 128kbps 48kHz. 음성은 Google 번역 음성 주소(`translate.googleapis.com/translate_tts`, 한국어)로 합성하고 loudnorm −16 LUFS로 정규화
