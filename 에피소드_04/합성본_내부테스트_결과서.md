## 1. 개요
- 테스트 대상: 사용자가 올린 `에피소드_04/최종영상/4번째_촬영영상.mp4`(HEVC 1920×1080, 회전 −90(세로), 104.9초, 15.75MB)로 만든 4편(앱 저장) 합성본
- 합성 방법: C(시각표 cuts.json). 얼굴 원형 크롭(`FACE_Y` 기본 0.35), 소리 −16 LUFS 정규화, 노이즈 제거·이퀄라이저 없음, 영상 우상단 배지 없음(DEC-041), 위치정보 제거. 공통 플레이어(`공통제작도구/player.html`)의 재현 화면 16장면에 합성
- 테스트 유형: 촬영본 분석 + 합성 + 자동 검수(12항목) + 재생 확인 + 소리-대본 대조(Whisper small) + 눈 검수
- 적용 Tier: Standard. 병렬: Whisper 설치와 촬영본 분석, 문구 작성(에이전트 3개)과 합성을 동시에 실행

## 2. 테스트 범위 및 제외 범위
- 범위: 장면 분할(16개), 합성 규격, 소리 위치·음량, 대본 일치, 얼굴 원형 배치, 하단 안전 영역, 위치정보, 재생
- 제외: **소리를 귀로 듣는 평가**(불가능), 얼굴 표정·입모양 싱크의 눈 검수(정지 프레임만 확인), 틱톡 업로드·라벨(사용자 몫), 노이즈 제거(필요 없다고 판단: 잡음 바닥 −46.9dB, 말 −24dB 안팎)

컨테이너 Linux 4코어, ffmpeg, Chromium(Playwright), Python 3, Whisper small(sherpa-onnx, GitHub 릴리스에서 이번 세션에 다시 설치). 도구: `공통제작도구/build_final.py`, `verify_final.py`, `verify_speech.py`, `play_check.js`.

## 8. 리스크 및 잔존 이슈
1. 장면 3은 사용자의 **두 번째 시도(25.70~27.78초)**를 썼다. 첫 시도를 NG로 판단한 근거는 "적어"에서 멈추고 2.5초 후 처음부터 다시 읽었다는 것이다. 사용자 확인 필요.
2. 소리를 귀로 듣지 못했다. 발음, 음질, 숨소리는 사용자가 영상을 들어 확인해야 한다.
3. Whisper가 "오류"를 숫자("5,6")로 듣는 등 일부 음절을 놓친다. 일치 여부는 "자기 > 이웃"으로만 판단했다.
4. 틱톡 업로드·"AI 생성 콘텐츠" 라벨·해시태그 규모는 사용자가 앱에서 확인한다(확인 필요).
